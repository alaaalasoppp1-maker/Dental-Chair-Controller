# ترحيل هويات الأرشيف القديم — Main 15.88.2 + Controller 3.7.6

## ما تم إصلاحه
- إضافة زر **معالجة هويات الأرشيف القديم** ضمن إعدادات أرشيف السحابة للإدارة.
- قراءة مرضى العيادة الحالية من Firestore عبر جلسة المستخدم الحالية، بدون Cloud Functions وبدون Blaze.
- المطابقة الآلية لا تعتمد على الاسم وحده.
- التطابق الآمن يعتمد على أحد الآتي:
  - `patientId` مطابق بدون تعارض واضح.
  - رقم الملف + الاسم.
  - رقم الملف + الهاتف.
  - اسم المجلد مطابق لـ رقم الملف + الاسم.
  - الهاتف + الاسم.
- إذا كان التطابق ضعيفاً أو يوجد أكثر من مرشح أو للمريض أرشيف مؤكد آخر، لا يتم تعديل المجلد ويظهر ضمن **يحتاج مراجعة**.
- قبل كتابة هوية جديدة يتم إنشاء `.dtdc-legacy-patient.json` كنسخة احتياطية من البيان القديم.
- يتم كتابة `clinicId + patientId` داخل `patient.json` مع الحفاظ على الحقول القديمة.
- زر **رفع الأرشيف المحلي الكامل إلى Drive** يشغّل ترحيل الهوية تلقائياً أولاً ثم يرفع المجلدات المؤكدة فقط.

## ماذا تفعل بعد التحديث
1. حدّث Main إلى 15.88.2 وانشر Hosting.
2. حدّث Controller إلى 3.7.6 وأعد بناء EXE.
3. افتح: أرشيف الصور السحابي → إعدادات الربط.
4. اضغط **معالجة هويات الأرشيف القديم** لرؤية التقرير.
5. راجع أي مجلدات بقيت ضمن يحتاج مراجعة.
6. اضغط **رفع الأرشيف المحلي الكامل إلى Drive**. هذا الزر يعيد تشغيل المطابقة الآمنة تلقائياً أيضاً.

## النشر
لا توجد تغييرات جديدة على Firestore rules في هذا التحديث. يكفي للـMain:

```powershell
firebase deploy --only hosting --project dr-taher-dental-chain
```

لا تستخدم Functions.
