# Controller 3.7.1 — إصلاح ربط الأرشيف القديم

## سبب المشكلة
الموقع كان يرسل `allowLegacyBind: true` بعد اختيار «نعم»، لكن الكونترولر كان يحوّل الأمر إلى `context.patient` ثم يستدعي `PatientArchive.select(context.patient)`، وبذلك كانت قيمة الموافقة تضيع قبل طبقة الأرشيف. لذلك كان الأرشيف يبقى Legacy ويظهر السؤال مرة أخرى في كل محاولة.

## الإصلاح
- تمرير `allowLegacyBind` صراحةً إلى `PatientArchive.select()`.
- بعد نجاح الربط، تثبيت `clinicId + patientId` داخل `patient.json` مع بقاء النسخة الاحتياطية القديمة كما هي.
- إضافة أرشيف المريض مباشرةً إلى طابور Google Drive بعد الربط. إذا كانت المزامنة فعّالة والـGoogle account مربوطاً يبدأ الرفع؛ وإلا يبقى الطابور محفوظاً ويكمل لاحقاً.
- لا يتم حذف أو نقل الصور القديمة.

## طريقة التطبيق
1. أغلق Controller بالكامل.
2. انسخ محتويات هذا الـZIP فوق مجلد/مستودع Controller 3.7.0 الحالي واختر Replace/Overwrite.
3. لا تغيّر `src/config/google-oauth.json` الموجود عندك؛ هذه الحزمة لا تحتويه أصلاً.
4. شغّل `npm ci` (أو استخدم node_modules الحالي إن كان البناء عندك عبر GitHub Actions).
5. شغّل `npm run check` ثم ابنِ النسخة الجديدة.
6. شغّل Controller 3.7.1 وافتح المريض. عند ظهور السؤال اختر «نعم» مرة واحدة فقط.

## النتيجة المتوقعة
- لا يعود سؤال الربط لنفس المريض.
- يظهر/يبقى نفس المجلد المحلي بدون خسارة ملفات.
- يدخل أرشيف المريض طابور Drive تلقائياً بعد الموافقة.
