# Dental Chair Controller 3.0.0

## ربط تطبيق المساعد

- يستقبل Controller سياق المريض والخطط من Dental Chain OS بعقد `dtdc-clinical-link-v1`.
- يميز اتصال `display` عن `doctor_assistant`، فلا يرسل بيانات الخطط الطبية إلى شاشة الكرسي ولا يرسل أوامر العرض إلى المساعد.
- يحفظ جلسات المساعد والوسائط في `09 - جلسات المساعد` داخل ملف المريض نفسه.
- يعيد نتائج الجلسة إلى Dental Chain OS عبر قناة loopback محلية، ولا يعتبر نهاية الجلسة إنهاءً للخطة.
- إنهاء الخطة حدث مستقل يرسله تطبيق المساعد بعد تأكيد الطبيب.

هذه الحزمة تخص **الكونترولر فقط**، ولا تستبدل تطبيق الشاشة أو Dental Chain OS أو تطبيق الألعاب.

## ملف المريض والاسم الكامل

- يستخدم الكونترولر مجلد المريض الموجود نفسه عبر رقم الملف وملف `_patient.json`.
- الاسم الكامل هو المعتمد في المجلد والحفظ؛ يبقى الاسم الأول للترحيب على الشاشة فقط.
- يدعم ترتيب `رقم الملف - الاسم الكامل` وكذلك `الاسم الكامل - رقم الملف` للمجلدات السابقة.
- صور البانوراما والمجلدات العربية الموجودة تُستخدم مباشرة، ولا تُنشأ نسخة موازية لها.

## الاستديو السريري اليدوي

- أربع خطوات واضحة: اختيار الصورة، الرسم السريري، مراحل العلاج، عرض المريض.
- لا توجد محركات تحليل شعاعي أو نماذج ذكاء اصطناعي أو تقارير تشخيص تلقائي.
- قلم يدوي يرسم شكلاً مغلقاً فوق الصورة ويملؤه بلون قابل لتعديل الشفافية.
- لوحة ألوان قابلة للإضافة والتسمية والتعديل والحذف، مثل: عاجل، بارد، مراقبة.
- اختيار الشكل أو مسحه، مع التراجع والإعادة وتعديل اللون ورقم السن بعد الرسم.
- ترقيم FDI كامل وربط كل رسم بالسن المعني.
- تنظيم الألوان ضمن مراحل علاج، مع إمكانية تعديل ارتباط كل لون وكل سن يدوياً.
- لكل مرحلة: الاسم، الشرح، الأولوية، الإنذار، الجلسات، المدة، التكلفة واللون.
- ست صور سنية توضيحية ثلاثية الأبعاد مدمجة، مع إمكانية استيراد صور مخصصة متكررة الاستخدام.
- خلفية مستقلة قابلة للاختيار لكل مرحلة، وتُنسخ مع الخطة داخل ملف المريض.
- عرض قصصي يبدأ بالبانوراما وحدها، ثم يضيف مجموعات الرسم بالتتابع، ثم يعرض كل مرحلة، ثم الخاتمة.
- أزرار البداية والسابق والتالي والخاتمة موجودة في الكونترولر فقط، ولا تظهر أي أزرار على شاشة المريض.
- حفظ الخطة والصورة المرسوم عليها وصور المراحل محلياً داخل مجلد المريض.
- الاختصار `Alt + I` يفتح الرسم السريري اليدوي مباشرة.

## التوافق

الإرسال يستخدم البروتوكول المحلي 4 مع تأكيد استلام وإعادة إرسال تلقائية، ويبقى متوافقاً مع Display القديم الذي يرسل `display_ready`. يوصى باستخدام Display 5.4.0 للفصل الصريح بين الأدوار.

## ملاحظة سريرية

الألوان والرسومات والمراحل مدخلات يدوية ينشئها الطبيب. البرنامج لا يقدم تشخيصاً تلقائياً ولا يجب اعتباره بديلاً عن الحكم السريري.
